# লুডো ব্যাকএন্ড: A থেকে Z

২ জনের ক্যাশ-ম্যাচ লুডো। সব গুরুত্বপূর্ণ সিদ্ধান্ত (ডাইস, চাল, কাটা, জেতা, টাকা) **সার্ভারে** হয়। ক্লায়েন্ট শুধু বোতাম চাপে ও ফলাফল দেখায়, তাই চিট করার সুযোগ নেই।

## ১. সংক্ষেপে নিয়ম

| বিষয় | নিয়ম |
|---|---|
| খেলোয়াড় | ঠিক **২ জন** (slot 1 ও slot 2) |
| টোকেন | প্রতি খেলোয়াড়ের **৪টি** (নম্বর 0, 1, 2, 3) |
| জেতার শর্ত | নিজের চারটি টোকেনই **৫৭** নম্বর ঘরে পৌঁছানো |
| বের হওয়া | টোকেন ঘর থেকে বের করতে **৬** লাগে |
| বাড়তি চাল | ৬ এলে আবার রোল |
| পরপর ৩ বার ৬ | তৃতীয়বারের ৬ বদলে ১-৫ এর একটা হয় |
| কাটা | প্রতিপক্ষের টোকেনের ঘরে পড়লে সেটা ঘরে ফেরত যায় (সেফ ঘর বাদে) |
| শেষ ঘর | **ঠিক সংখ্যা** না এলে ৫৭ ছাড়িয়ে যাওয়া চাল অবৈধ |

## ২. টোকেনের পজিশন

প্রতিটি টোকেনের একটা সংখ্যা আছে (`player1Tokens`, `player2Tokens`):

| পজিশন | মানে |
|---|---|
| `0` | ঘরে (yard), এখনো বের হয়নি |
| `1` | নিজের স্টার্ট ঘর |
| `1` থেকে `51` | শেয়ার্ড ট্র্যাক (দুজনেই এই পথে চলে) |
| `52` থেকে `56` | নিজের হোম কলাম (প্রতিপক্ষ ঢুকতে পারে না, কাটাও পড়ে না) |
| `57` | পৌঁছে গেছে (HOME) |

**শেয়ার্ড ট্র্যাক:** মোট ৫২ ঘর (0 থেকে 51)।
- slot 1 এর পজিশন `1` = ট্র্যাকের ঘর `0`
- slot 2 এর পজিশন `1` = ট্র্যাকের ঘর `26` (বিপরীত দিক)

সূত্র: `ট্র্যাক ঘর = (পজিশন - 1 + স্টার্ট অফসেট) % 52`

**সেফ ঘর:** ট্র্যাকের `0, 8, 13, 21, 26, 34, 39, 47`। এখানে কাটা পড়ে না।

### চাল বৈধ কি না

```
টোকেন ঘরে (0)      -> শুধু ডাইস ৬ হলে বৈধ, নতুন পজিশন 1
টোকেন ৫৭ এ         -> আর চলবে না
অন্য পজিশন         -> পজিশন + ডাইস <= 57 হলে বৈধ
```

যেমন টোকেন `55` এ আছে: ডাইস ১ বা ২ হলে চলবে, ৩ বা তার বেশি হলে চলবে না।

## ৩. টাকার হিসাব

| এন্ট্রি ফি | প্রাইজ (বিজয়ী পায়) | কমিশন |
|---|---|---|
| 11 | 20 | 2 |
| 23 | 40 | 6 |
| 45 | 80 | 10 |
| 113 | 200 | 26 |
| 217 | 400 | 34 |
| অন্য | ফি × 1.8 (নিচের দিকে ২ দশমিক পর্যন্ত) | বাকিটা |

কমিশন = (ফি × ২) − প্রাইজ।

**কখন কী হয়:**
- **প্রথম রোলে** দুজনের ফি একসাথে কাটে (কারো ব্যালেন্স কম থাকলে ম্যাচ বাতিল)।
- **বিজয়ী** প্রাইজ পায় withdraw ব্যালেন্সে।
- **রিফান্ড** গেলে ফি ফেরত যায় deposit ব্যালেন্সে।
- প্রতিটি লেনদেন `WalletTransaction` এ লেখা থাকে: `ENTRY_FEE`, `WIN`, `REFUND`, `COMMISSION`।

## ৪. ম্যাচের জীবনচক্র

```
MATCH_FOUND --(কাউন্টডাউন শেষ)--> ONGOING --(কেউ জিতলে)--> FINISHED
     |                              |
     |                              +--(রিফান্ড/বাতিল)--> CANCELLED
     +--(কেউ শুরু না করলে)---------------------------------> CANCELLED
```

1. **ম্যাচ খোঁজা:** দুজন ইউজার `/api/match/start` কল করে। মিলে গেলে `GameSession` তৈরি হয়, স্ট্যাটাস `MATCH_FOUND`, `matchStartTimestamp` এ কাউন্টডাউন শেষের সময় বসে।
2. **শুরু:** `GameCleanupTask` প্রতি ১০ সেকেন্ডে দেখে কাউন্টডাউন শেষ হয়েছে কি না। হলে স্ট্যাটাস `ONGOING` ও `GAME_STARTED` ইভেন্ট। প্রথম পালা slot 1 এর।
3. **খেলা:** রোল, চাল, রোল, চাল... (পরের অংশে)।
4. **শেষ:** চারটি টোকেন ৫৭ এ পৌঁছালে সার্ভার নিজেই বিজয়ী ঘোষণা করে, প্রাইজ দেয়, স্ট্যাটাস `FINISHED`।

## ৫. একটা পালা কীভাবে চলে

প্রতি পালায় দুটো ধাপ: **রোল**, তারপর **চাল**।

```
খেলোয়াড় ----POST /roll---->  সার্ভার ডাইস ফেলে
                               বৈধ চাল আছে কি না দেখে
                  canMove = true  --> খেলোয়াড় টোকেন বেছে POST /move
                  canMove = false --> পালা নিজে থেকেই চলে যায়
```

### সার্ভারের ভেতরে (roll)
1. সেশন রো লক হয় (একসাথে দুটো কাজ চলতে পারে না)।
2. চেক: খেলা `ONGOING`, তার পালা, আগের চাল বাকি নেই।
3. প্রথম রোল হলে দুজনের ফি কাটে।
4. `0-6` এর র‍্যান্ডম ডাইস (SecureRandom)।
5. পরপর তৃতীয় ৬ হলে ১-৫ এ বদল।
6. বৈধ চাল থাকলে `pendingMove = true`।
7. ৬ হলে একই খেলোয়াড়ের আবার পালা, নইলে অপরজনের।

### সার্ভারের ভেতরে (move)
1. সেশন লক, চেক: খেলা চলছে, `pendingMove` আছে, **ডাইস যে ফেলেছে সে-ই** চাল দিচ্ছে।
2. `tokenIndex` ০ থেকে ৩ হতে হবে।
3. নতুন পজিশন হিসাব। অবৈধ হলে এরর।
4. টোকেন সরানো।
5. শেয়ার্ড ট্র্যাকে সেফ নয় এমন ঘরে প্রতিপক্ষের টোকেন থাকলে সেগুলো `0` তে ফেরত।
6. `pendingMove = false`।
7. চারটি টোকেন `57` হলে `declareWinner` একই ট্রানজেকশনে।

> **কেন `diceOwner` দিয়ে চাল?** ধরুন slot 1 এ ডাইস ৩ এলো। রোলের সাথেই `currentPlayer` slot 2 হয়ে যায়, কিন্তু চাল দেওয়ার কথা slot 1 এর। তাই চাল সবসময় `diceOwner` দেয়, `currentPlayer` নয়। চাল শেষ না হওয়া পর্যন্ত কেউই নতুন রোল করতে পারে না।

### উদাহরণ

| ধাপ | ঘটনা | ফল |
|---|---|---|
| ১ | P1 রোল, ডাইস 4, সব টোকেন ঘরে | `canMove=false`, পালা P2 তে |
| ২ | P2 রোল, ডাইস 6 | `canMove=true`, P2 কে চাল দিতে হবে |
| ৩ | P2 `/move` `{tokenIndex:0}` | টোকেন 0: `0 -> 1`, P2 আবার রোল করবে (৬ এসেছিল) |
| ৪ | P2 রোল, ডাইস 3 | `canMove=true` |
| ৫ | P2 `/move` `{tokenIndex:0}` | টোকেন 0: `1 -> 4`, পালা P1 এ |

## ৬. API

সব রিকোয়েস্টে হেডার: `Authorization: Bearer <JWT>`। JWT থেকে `gameId` বের হয়, এর বাইরে ক্লায়েন্ট নিজের পরিচয় পাঠাতে পারে না।

### `POST /api/game/roll/{sessionId}`
রেসপন্স:
```json
{
  "sessionId": 12,
  "event": "DICE_ROLLED",
  "dice": 6,
  "rolledBy": 2,
  "nextPlayer": 2,
  "canMove": true,
  "message": "OK"
}
```
- `canMove: true` হলে `rolledBy` খেলোয়াড় `/move` কল করবে।
- ব্যালেন্স কম হলে `event: "GAME_CANCELLED"`।

### `POST /api/game/move/{sessionId}`
বডি: `{"tokenIndex": 0}` (০ থেকে ৩)

রেসপন্স:
```json
{
  "sessionId": 12,
  "event": "TOKEN_MOVED",
  "movedBy": 2,
  "token": 0,
  "from": 0,
  "to": 1,
  "captured": 0,
  "nextPlayer": 2,
  "finished": false,
  "winnerGameId": null,
  "player1Tokens": [0, 0, 0, 0],
  "player2Tokens": [1, 0, 0, 0]
}
```
ক্লায়েন্ট সবসময় `player1Tokens` ও `player2Tokens` দিয়ে বোর্ড আঁকবে, নিজে হিসাব করবে না।

### `POST /api/game/leave/{sessionId}`
ইউজার ব্যাক/কুইট দিলে কল করবে (নিয়ম পরের অংশে)।

### `GET /game/history`
নিজের খেলার ইতিহাস।

### এরর
`400` বার্তাসহ (`Not your turn`, `No move pending`, `Invalid move for this token`, `Previous move pending`, `Game not active`), `401` টোকেন না থাকলে, `500` অন্য সমস্যায়।

## ৭. WebSocket

| টপিক | কী আসে |
|---|---|
| `/topic/game/{sessionId}` | `DICE_ROLLED`, `TOKEN_MOVED` |

শেষ/শুরুর ইভেন্ট ডেটাবেস **কমিট হওয়ার পরে** যায়, তাই রোলব্যাক হলে ক্লায়েন্টের কাছে ভুল খবর পৌঁছায় না। ক্লায়েন্টকে দুটো টপিকেই সাবস্ক্রাইব করতে হবে।

## ৮. বের হওয়া, ডিসকানেক্ট, টাইমআউট

### কেউ `leave` করলে বা ডিসকানেক্ট (রিকানেক্টের সময় শেষে)

| অবস্থা | ফল |
|---|---|
| কেউ রোল করেনি (ফি কাটা হয়নি) | ম্যাচ বাতিল, টাকা লেনদেন নেই |
| ফি কাটা, কিন্তু একজন এখনো রোল করেনি | বাতিল, **দুজনকে ফি ফেরত** |
| দুজনেই রোল করেছে, খেলা চলছে | যে বের হয়েছে সে **হারে**, অপরজন প্রাইজ পায় |
| খেলা আগেই শেষ/বাতিল | কিছু হয় না |

ডিসকানেক্ট হলে `GameDisconnectListener` অপেক্ষা করে (প্রায় ২০ সেকেন্ড), না ফিরলে `leave` চালায়।

### অটো টাইমআউট (`GameCleanupTask`, প্রতি ১০ সেকেন্ডে)

| ঘটনা | সময় | ফল |
|---|---|---|
| কাউন্টডাউন শেষ | কাউন্টডাউন অনুযায়ী | `MATCH_FOUND -> ONGOING` |
| ফি কাটার পর অপরজন প্রথম রোল করেনি | **৬০ সেকেন্ড** | বাতিল, দুজনকে রিফান্ড |
| কেউই রোল করেনি | **২ মিনিট** | বাতিল |

## ৯. চিট থেকে সুরক্ষা

- ডাইস সার্ভারে ফেলা হয়।
- টোকেন নড়ে শুধু সার্ভারে, ক্লায়েন্ট নিজের টোকেন পজিশন পাঠাতে পারে না।
- বিজয়ী ক্লায়েন্ট জানাতে পারে না, সার্ভার নিজে ঠিক করে।
- ডাবল রোল, ডাবল চাল, অন্যের পালায় চাল আটকানো আছে।
- প্রাইজ একবারই যায় (`ONGOING` না হলে `declareWinner` কিছু করে না)।
- সেশন রো লক, তাই একই ম্যাচে দুটো রিকোয়েস্ট একসাথে চলতে পারে না।
- রেসপন্সে ইউজারের পাসওয়ার্ড/মোবাইল/ব্যালেন্স যায় না, শুধু দরকারি ফিল্ড।

## ১২. টেস্ট চেকলিস্ট (২ ইউজারে)

1. ম্যাচ হয়, কাউন্টডাউনের পর `GAME_STARTED` আসে
2. প্রথম রোলে দুজনের ব্যালেন্স থেকে ফি কাটে
3. ৬ ছাড়া রোলে `canMove=false`, পালা বদলে যায়
4. ৬ এ `/move` দিলে টোকেন `0 -> 1`, আবার রোলের সুযোগ
5. `/move` না দিয়ে আবার `/roll` দিলে `Previous move pending` এরর
6. অন্যের টোকেন নম্বরে বা ভুল পালায় `/move` দিলে এরর
7. সেফ নয় এমন ঘরে প্রতিপক্ষকে কাটলে `captured > 0`
8. ৫৭ ছাড়িয়ে যাওয়া চাল অবৈধ
9. চারটি টোকেন ৫৭ এ গেলে `finished: true`, প্রাইজ জমা
10. খেলার মাঝে `leave` দিলে অপরজন জেতে
11. প্রথম রোলের পর অপরজন ৬০ সেকেন্ড রোল না করলে রিফান্ড
